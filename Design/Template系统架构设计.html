3. 数据模型

3.0 表关系总览

┌──────────────────────┐ │ template_config │ │ (模板配置) │ │ id BIGINT PK │──1──┐ │ name VARCHAR(200) │ │ 1 │ is_active TINYINT │ │ └──────────────────────┘ │ │ │ │ 1 │ ├────────┐ │ │ N │ N │ ┌───────▼──────────┐ │ │ template_rule │ │ │ (样式规则) │ │ │ template_id FK───┼────────┘ │ name, font_name │ │ font_size, bold │ │ italic, underline │ │ color, align │ │ indent, spacing │ └──────────────────┘ │ ┌──────────▼───────────┐ │ template_engine_config│ │ (识别引擎配置) │ │ template_id FK UNIQUE ├── 1:1 │ cover_pattern TEXT │ │ toc_pattern TEXT │ │ title_patterns TEXT │ │ body_pattern TEXT │ └──────────────────────┘ ┌──────────────────────────┐ │ user_upload_file │ │ (用户上传文件) │ │ template_id BIGINT │── N:1 ──→ template_config │ original_content LONGBLOB│ │ parsed_content LONGBLOB│ │ parsed_json MEDIUMTEXT│ │ manual_adjust_json │ │ output_content LONGBLOB│ │ status VARCHAR(20) │ └──────────────────────────┘

1:N template_config → template_rule

一个模板包含多个样式规则。删除模板时级联删除其下所有规则（CASCADE）。

1:1 template_config → template_engine_config

一个模板有且仅有一个引擎配置。UNIQUE 约束保证一对一。

1:N template_config → user_upload_file

一个模板可被多个上传文件使用。删除模板时文件表 template_id 置 NULL（SET NULL）。

三态逻辑 样式字段设计

NULL = 保持原文不变  |  0 = 明确关闭  |  1 = 明确开启

3.1 模板信息配置表 template_config

CREATE TABLE template_config (
    id          BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    name        VARCHAR(200) NOT NULL                 COMMENT '规则模板名称',
    is_active   TINYINT      NOT NULL DEFAULT 1       COMMENT '是否有效：1=有效, 0=停用',
    created_at  DATETIME     NOT NULL DEFAULT NOW()   COMMENT '创建时间',
    updated_at  DATETIME     NOT NULL DEFAULT NOW() ON UPDATE NOW(),
    PRIMARY KEY (id),
    INDEX idx_name (name),
    INDEX idx_is_active (is_active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='模板信息配置表';
字段类型必填默认值业务说明
idBIGINT是AUTO系统自增主键
nameVARCHAR(200)是-模板名称，界面展示。建议唯一，由业务层校验
is_activeTINYINT是1逻辑删除开关。停用后历史数据仍可查看，新建解析任务不可选
created_atDATETIME是NOW()插入时自动填充
updated_atDATETIME是NOW()自动更新为当前时间

3.2 模板规则样式配置表 template_rule

CREATE TABLE template_rule (
    id              BIGINT        NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    template_id     BIGINT        NOT NULL                 COMMENT '所属模板ID',
    name            VARCHAR(200)  NOT NULL                 COMMENT '样式规则名称',
    -- 字体相关
    font_name       VARCHAR(100)  DEFAULT NULL             COMMENT '字体名称',
    font_size       INT           DEFAULT NULL             COMMENT '字号(磅值)',
    font_bold       TINYINT       DEFAULT NULL             COMMENT '是否加粗：1=是, 0=否, NULL=不修改',
    font_italic     TINYINT       DEFAULT NULL             COMMENT '是否斜体',
    font_underline  TINYINT       DEFAULT NULL             COMMENT '是否下划线',
    font_color      VARCHAR(20)   DEFAULT NULL             COMMENT '字体颜色 十六进制 #RRGGBB',
    font_strike     TINYINT       DEFAULT NULL             COMMENT '是否删除线',
    -- 段落相关
    text_align      VARCHAR(20)   DEFAULT NULL             COMMENT '对齐：LEFT/CENTER/RIGHT/JUSTIFY',
    text_indent     DECIMAL(10,2) DEFAULT NULL             COMMENT '首行缩进(字符数)',
    line_spacing    DECIMAL(10,2) DEFAULT NULL             COMMENT '行距(倍数)',
    space_before    DECIMAL(10,2) DEFAULT NULL             COMMENT '段前间距(磅)',
    space_after     DECIMAL(10,2) DEFAULT NULL             COMMENT '段后间距(磅)',
    highlight_color VARCHAR(20)   DEFAULT NULL             COMMENT '预览高亮底色',
    created_at      DATETIME      NOT NULL DEFAULT NOW(),
    updated_at      DATETIME      NOT NULL DEFAULT NOW() ON UPDATE NOW(),
    PRIMARY KEY (id),
    INDEX idx_template_id (template_id),
    CONSTRAINT fk_rule_template FOREIGN KEY (template_id)
        REFERENCES template_config(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='模板规则样式配置表';

三态逻辑：所有样式字段（bold/italic/underline/strike）采用 NULL/0/1 三态设计，NULL 表示不修改原文样式。

3.3 内容识别引擎配置表 template_engine_config

CREATE TABLE template_engine_config (
    id              BIGINT      NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    template_id     BIGINT      NOT NULL                 COMMENT '关联模板ID',
    cover_pattern   TEXT        DEFAULT NULL             COMMENT '封面识别正则',
    toc_pattern     TEXT        DEFAULT NULL             COMMENT '目录识别正则',
    title_patterns  TEXT        DEFAULT NULL             COMMENT '标题识别规则(JSON数组)',
    body_pattern    TEXT        DEFAULT NULL             COMMENT '正文识别正则',
    created_at      DATETIME    NOT NULL DEFAULT NOW(),
    updated_at      DATETIME    NOT NULL DEFAULT NOW() ON UPDATE NOW(),
    PRIMARY KEY (id),
    UNIQUE INDEX uk_template_id (template_id),
    CONSTRAINT fk_engine_template FOREIGN KEY (template_id)
        REFERENCES template_config(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

title_patterns JSON 格式

[
  {"pattern": "^第.{1,20}章", "level": 1, "rule_id": 2, "description": "匹配第X章"},
  {"pattern": "^第.{1,20}节", "level": 2, "rule_id": 3, "description": "匹配第X节"},
  {"pattern": "^\\d+\\.\\d+\\s", "level": 3, "rule_id": 4, "description": "匹配1.1 "},
  {"pattern": "^(一|二|三|四|五)+[、，]", "level": 2, "rule_id": 3}
]

匹配优先级：封面 → 目录 → 标题(按 level 升序) → 正文

3.4 用户上传文件表 user_upload_file

CREATE TABLE user_upload_file (
    id                  BIGINT        NOT NULL AUTO_INCREMENT  COMMENT '主键ID',

4. API 设计

4.1 模板维护 /api/template

方法路径说明
POST/api/template新增规则模板
GET/api/template/{id}查看模板详情（含规则列表 + 引擎配置）
GET/api/template/list查看所有规则模板（分页）
PUT/api/template/{id}修改规则模板基本信息
PUT/api/template/{id}/toggle启用/禁用模板

4.2 模板规则 /api/template/{templateId}/rule

方法路径说明
POST/api/template/{templateId}/rule新增样式规则
GET/api/template/{templateId}/rule/{id}查看规则详情
GET/api/template/{templateId}/rule/list查看模板下所有规则
PUT/api/template/{templateId}/rule/{id}修改样式规则
DELETE/api/template/{templateId}/rule/{id}删除样式规则

4.3 识别引擎配置 /api/template/{templateId}/engine

方法路径说明
PUT/api/template/{templateId}/engine保存/更新识别引擎配置
GET/api/template/{templateId}/engine查看识别引擎配置

4.4 Word 文件格式化 /api/word

方法路径说明
GET/api/word/list查看所有上传文件
POST/api/word/upload上传 Word 文件 (multipart)
POST/api/word/{id}/parse解析文件
GET/api/word/{id}/preview获取预览数据（JSON：匹配信息 + pdfUrl + 图例）
GET/api/word/{id}/preview/pdfv1.1 获取预览 PDF 文件（application/pdf 二进制流）
PUT/api/word/{id}/adjust保存人工调整结果
POST/api/word/{id}/export导出格式化 Word 文件
GET/api/word/{id}/download下载导出文件

5. 内容识别引擎设计

工作流程

1. 提取段落文本 → 2. 封面正则匹配 → 3. 目录正则匹配 → 4. 标题正则匹配 → 5. 剩余→正文 → 6. 输出JSON映射

匹配优先级：封面 > 目录 > 标题(按 level 升序) > 正文。一旦某个段落被高优先级规则命中，不再参与后续匹配。

8. 约束与风险

约束 / 风险应对策略
仅支持 .docx (Office 2007+) Apache POI 不支持旧 .doc 格式，前端上传时校验文件扩展名，后端校验 Content-Type
大文件 BLOB 存储 LONGBLOB 最大 4GB，应用层限制上传 50MB（Spring Multipart 配置）
正则规则匹配精度 复杂排版可能识别不准，提供人工调整功能兜底
单用户无权限 当前不做登录认证，后续可扩展 Spring Security + JWT
并发解析性能 单个文件解析，当前无并发压力。后续可引入任务队列
v1.1 PDF 转换质量 POI+PDFBox 纯 Java 方案可能无法完美还原复杂文档排版。提供 LibreOffice headless 兜底方案，通过配置切换
v1.1 文本高亮定位精度 PDF.js 文本位置与段落匹配可能存在偏移（特别是中文文档）。采用模糊匹配 + 包围盒近似 + 人工校对兜底
v1.1 大文件 PDF 传输 含图片的 PDF 可能较大，Base64 传输消耗带宽。提供独立 PDF 流式端点，浏览器原生缓存

9. 预览功能重构设计（v1.1 新增）

新增 2026-05-07 — 基于用户需求：预览效果对齐 Office Word + 分页 + 文本高亮 + 右侧图例

9.1 重构动机

原预览方案采用逐段落 div 卡片渲染，存在以下本质差距：

维度旧方案（div 卡片）新方案（PDF.js）
渲染保真度独立卡片，丢失 Word 连续排版效果PDF 精确还原 Word 页面布局
分页无分页概念一个预览页 = Word 一个页面
内容完整性表格/图片/页眉页脚丢失；文本截断 200 字符全部保留，零丢失
高亮粒度整段卡片底色Canvas 叠加层精确覆盖匹配文本
图例位置顶部水平排列右侧固定悬浮面板

9.2 整体架构

┌──────────────────────────────────────────────────────────────────┐ │ 预览链路（PDF 展示） │ │ │ │ original_content (.docx bytes) │ │ │ │ │ ▼ │ │ PdfConversionService │ │ ├── PoiPdfConversionService (默认，纯 Java) │ │ └── LibreOfficePdfConversionService (兜底，高质量) │ │ │ │ │ ▼ │ │ PDF 字节流 ──────── GET /api/word/{id}/preview/pdf │ │ │ │ │ ▼ │ │ 前端 PDF.js 按页渲染 Canvas │ │ │ │ │ ├── 文本高亮叠加层 (Canvas) — 根据匹配信息绘制底色矩形 │ │ ├── 右侧固定图例面板 (LegendPanel) — 底色↔规则对应关系 │ │ └── 手动调整交互 — 保留原有下拉选择 matchedType 功能 │ │ │ │ 匹配信息来源（优先级）： │ │ manualAdjustJson (用户调整后) > parsedJson (自动识别) │ └──────────────────────────────────────────────────────────────────┘ ┌──────────────────────────────────────────────────────────────────┐ │ 导出链路（Word 下载） │ │ │ │ original_content → POI XWPFDocument → applyStyles() │ │ │ │ │ ▼ │ │ output_content (.docx) ─── 用户下载格式化后 Word 文件 │ │ │ │ ★ PDF 仅用于预览，下载始终保持 .docx 格式 │ └──────────────────────────────────────────────────────────────────┘

9.3 手动调整闭环

1. 上传 & 解析 → 2. 首次预览 (PDF) → 3. 手动调整 matchedType → 4. 保存 (manualAdjustJson) → 5. 再次预览 (重新生成 PDF)

Preview 阶段匹配源优先级：manualAdjustJson > parsedJson。 若使用 manualAdjustJson，后端自动回填 ruleId / ruleName。 PDF 始终基于 original_content 生成，与匹配源无关。

9.4 PDF 转换策略

配置值实现类原理质量部署要求
poi（默认） PoiPdfConversionService Apache POI 读取 .docx → Apache PDFBox 构建 PDF 中等（纯文本型文档足够） 零外部依赖
libreoffice LibreOfficePdfConversionService ProcessBuilder 调用 LibreOffice headless 转换 高（完美还原 Word 排版） 需安装 LibreOffice 
# application.yml 配置
template:
  pdf:
    converter: poi                # poi | libreoffice
    libreoffice:
      path: soffice               # LibreOffice 可执行文件路径
      timeout-seconds: 30         # 转换超时秒数
    cache:
      enabled: true               # 是否缓存 PDF
      ttl-minutes: 5              # 缓存有效期

降级策略：LibreOffice 转换失败时自动降级到 POI 模式，记录 WARN 日志。

9.5 前端 PDF.js 集成

依赖版本用途
pdfjs-distv4.x（Mozilla 官方）PDF 解析 + Canvas 渲染 + 文本提取

组件结构

高亮匹配算法

  1. PDF.js page.getTextContent() 获取每页文本项（含 str, transform, width, height）
  2. 将文本项按顺序拼接为页面文本字符串
  3. 遍历 matches 中每个段落文本，在页面文本中模糊匹配（编辑距离 ≤3）
  4. 根据匹配到的文本项 transform 计算包围盒（bounding box）
  5. 在叠加 Canvas 上绘制半透明底色矩形（opacity: 0.25，带 3px 彩色左边框）

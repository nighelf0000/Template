# 智能匹配算法功能设计文档

## 1. 概述

在现有模板系统的引擎配置页面中，新增基于 TF-IDF + 文本相似度的智能匹配算法功能，允许用户通过训练已处理文件（EXPORTED/ADJUSTED 状态）的 `parsed_json` 数据自动生成匹配规则，并在识别流程中手动切换智能匹配模式与正则匹配模式。

## 3. 数据模型

### 3.1 新建表 DDL

```sql
-- 智能匹配训练任务表
CREATE TABLE IF NOT EXISTS smart_match_task (
    id              BIGINT        NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    template_id     BIGINT        NOT NULL                 COMMENT '关联模板ID',
    task_name       VARCHAR(200)  NOT NULL                 COMMENT '任务名称',
    status          VARCHAR(20)   NOT NULL DEFAULT 'PENDING' COMMENT '任务状态：PENDING/RUNNING/SUCCESS/FAILED',
    progress        INT           NOT NULL DEFAULT 0       COMMENT '处理进度(0-100)',
    file_count      INT           NOT NULL DEFAULT 0       COMMENT '训练文件数',
    error_message   VARCHAR(2000) DEFAULT NULL             COMMENT '错误信息',
    rule_count      INT           DEFAULT NULL             COMMENT '生成的规则数量',
    started_at      DATETIME      DEFAULT NULL             COMMENT '开始训练时间',
    completed_at    DATETIME      DEFAULT NULL             COMMENT '完成时间',
    created_at      DATETIME      NOT NULL DEFAULT NOW()   COMMENT '创建时间',
    updated_at      DATETIME      NOT NULL DEFAULT NOW() ON UPDATE NOW() COMMENT '最后修改时间',
    PRIMARY KEY (id),
    INDEX idx_template_id (template_id),
    INDEX idx_status (status),
    CONSTRAINT fk_task_template FOREIGN KEY (template_id) REFERENCES template_config(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='智能匹配训练任务表';

-- 智能匹配规则表
CREATE TABLE IF NOT EXISTS smart_match_rule (
    id              BIGINT        NOT NULL AUTO_INCREMENT  COMMENT '主键ID',
    template_id     BIGINT        NOT NULL                 COMMENT '关联模板ID',
    task_id         BIGINT        DEFAULT NULL             COMMENT '来源训练任务ID',
    rule_name       VARCHAR(200)  NOT NULL                 COMMENT '规则名称',
    match_type      VARCHAR(20)   NOT NULL DEFAULT 'TITLE' COMMENT '匹配类型：COVER/TOC/TITLE/BODY',
    match_level     INT           DEFAULT NULL             COMMENT '标题级别（TITLE专用）',
    keywords        TEXT          NOT NULL                 COMMENT '关键词/特征描述',
    feature_vector  MEDIUMTEXT    NOT NULL                 COMMENT 'TF-IDF特征向量JSON（训练结果）',
    style_rule_id   BIGINT        DEFAULT NULL             COMMENT '关联样式规则ID(template_rule)',
    threshold       DECIMAL(5,4)  NOT NULL DEFAULT 0.3000  COMMENT '相似度阈值(0-1)',
    is_active       TINYINT       NOT NULL DEFAULT 1       COMMENT '是否启用：1=启用, 0=停用',
    match_order     INT           NOT NULL DEFAULT 0       COMMENT '匹配顺序',
    created_at      DATETIME      NOT NULL DEFAULT NOW()   COMMENT '创建时间',
    updated_at      DATETIME      NOT NULL DEFAULT NOW() ON UPDATE NOW() COMMENT '最后修改时间',
    PRIMARY KEY (id),
    INDEX idx_template_id (template_id),
    INDEX idx_task_id (task_id),
    INDEX idx_match_type (match_type),
    INDEX idx_is_active (is_active),
    CONSTRAINT fk_smr_template FOREIGN KEY (template_id) REFERENCES template_config(id) ON DELETE CASCADE,
    CONSTRAINT fk_smr_task FOREIGN KEY (task_id) REFERENCES smart_match_task(id) ON DELETE SET NULL,
    CONSTRAINT fk_smr_rule FOREIGN KEY (style_rule_id) REFERENCES template_rule(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='智能匹配规则表';
```

### 3.2 数据流

```
用户点击"智能匹配算法"按钮
    │
    ▼
后端触发训练任务，生成 smart_match_task 记录（status=PENDING）
    │
    ▼
异步线程启动（@Async），更新任务状态为 RUNNING
    │
    ▼
查询当前模板下所有 status IN ('EXPORTED','ADJUSTED') 的 user_upload_file
    │
    ▼
遍历文件，提取每个文件的 parsed_json 数据
 → 按段落解析：文本内容 + matched_type + ruleId + ruleName
 → 按 matched_type 分组聚合同类文本
    │
    ▼
构建训练数据 JSON，通过 ProcessBuilder 调用 Python 脚本
    │
    ▼
Python 脚本执行 TF-IDF 训练：
 → 对每组（同一 match_type）的文本集合进行 TF-IDF 向量化
 → 计算文本间余弦相似度，聚类出代表性的规则
 → 为每个规则输出：match_type + 关键词 + 特征向量 + 阈值
    │
    ▼
Python 脚本输出结果 JSON 到 stdout
    │
    ▼
Java 读取 stdout，解析结果
 → 将每条规则写入 smart_match_rule 表
 → 更新 smart_match_task 记录（status=SUCCESS, rule_count）
    │
    ▼
前端轮询获取任务状态和进度
 → 任务完成后显示生成的规则列表
```

### 3.3 与现有表的关系

```
template_config (1) ──→ (N) smart_match_task
template_config (1) ──→ (N) smart_match_rule
smart_match_task (1) ──→ (N) smart_match_rule
template_rule (1) ──→ (N) smart_match_rule (style_rule_id)
user_upload_file (N) ──→ 训练数据来源（无外键，通过status过滤）
```

## 4. 接口定义

所有新增 API 遵循 `/api/smart-match` 前缀。

### 4.1 触发智能匹配训练
| 项目 | 内容 |
|------|------|
| 路径 | `POST /api/smart-match/{templateId}/train` |
| 响应 | `ApiResponse<SmartMatchTask>` |
| 说明 | 异步触发训练，立即返回任务记录（status=PENDING） |

### 4.2 查询训练任务列表
| 项目 | 内容 |
|------|------|
| 路径 | `GET /api/smart-match/{templateId}/tasks` |
| 请求参数 | `page`, `size` |
| 响应 | `ApiResponse<Page<SmartMatchTask>>` |

### 4.3 查询训练任务详情
| 项目 | 内容 |
|------|------|
| 路径 | `GET /api/smart-match/{templateId}/tasks/{taskId}` |
| 响应 | `ApiResponse<SmartMatchTask>` |

### 4.4 查询智能匹配规则列表
| 项目 | 内容 |
|------|------|
| 路径 | `GET /api/smart-match/{templateId}/rules` |
| 请求参数 | `page`, `size` |
| 响应 | `ApiResponse<Page<SmartMatchRule>>` |

### 4.5 切换规则启用状态
| 项目 | 内容 |
|------|------|
| 路径 | `PUT /api/smart-match/{templateId}/rules/{ruleId}/toggle` |
| 响应 | `ApiResponse<Void>` |

### 4.6 编辑智能匹配规则
| 项目 | 内容 |
|------|------|
| 路径 | `PUT /api/smart-match/{templateId}/rules/{ruleId}` |
| 请求体 | `{ ruleName, matchType, matchLevel, styleRuleId, threshold, isActive }` |
| 响应 | `ApiResponse<SmartMatchRule>` |

### 4.7 测试智能匹配
| 项目 | 内容 |
|------|------|
| 路径 | `POST /api/smart-match/{templateId}/test` |
| 请求体 | `multipart/form-data`: `file` (Word .docx) |
| 响应 | `ApiResponse<List<SmartMatchTestResult>>` |
| 响应结构 | `[{ paragraphIndex, text, matchedType, matchLevel, styleRuleId, ruleName, confidence }]` |

### 4.8 删除规则
| 项目 | 内容 |
|------|------|
| 路径 | `DELETE /api/smart-match/{templateId}/rules/{ruleId}` |
| 响应 | `ApiResponse<Void>` |

## 5. 技术选型

### 5.1 后端
| 技术 | 用途 |
|------|------|
| Spring Boot 3.2.5 | Web 应用框架 |
| MyBatis-Plus 3.5.6 | ORM |
| MySQL 8.0+ | 数据库 |

| @Async / ThreadPoolTaskExecutor | 异步任务 |

|------|------|
| Vue 3 (composition API) | 前端框架 |
| Element Plus 2.13.7 | UI 组件库 |
| TypeScript 6.0 | 类型安全 |
| Axios 1.16 | HTTP 请求 |

### 5.3 Python 算法
| 技术 | 用途 |
|------|------|
| Python 3.10+ | 运行环境 |
| scikit-learn 1.3+ | TF-IDF + 余弦相似度 |
| numpy 1.24+ | 数值计算 |
| jieba 0.42+ | 中文分词 |

### 5.4 Python 脚本接口规范

输入（stdin JSON）：
```json
{
  "template_id": 1,
  "training_data": [
    {
      "match_type": "TITLE",
      "match_level": 1,
      "texts": ["第一章 总则", "第二章 组织机构"],
      "style_rule_id": 1
    }
  ]
}
```

输出（stdout JSON）：
```json
{
  "success": true,
  "rules": [
    {
      "match_type": "TITLE",
      "match_level": 1,
      "keywords": ["第", "章"],
      "feature_vector": [...],
      "threshold": 0.3,
      "style_rule_id": 1
    }
  ]
}
```

## 6. 约束与风险

| 风险 | 应对方案 |
|------|----------|
| Python 未安装 | application.yml 配置路径，启动时检测，友好提示 |
| 中文分词效果 | 使用 jieba 分词库预处理 |
| 大数据量 parsed_json | 分批处理，只提取必要字段 |
| 训练耗时长 | 异步 + 前端进度 + 超时机制（默认10分钟） |
| 子进程阻塞 | `process.waitFor(timeout, unit)` + 超时销毁 |
| 并发训练冲突 | 同模板下同时只允许一个训练任务 |

## 1. 概述

### 1.1 整体目标

训练结果查看功能的目标是：为模板训练生成的解析结果提供**多层次、可交互、可对比**的可视化查看能力。用户需要能够：

1. **宏观概览**：查看某个训练任务下所有文件的解析结果列表，快速了解成功/失败状态
2. **结构化浏览**：选中一个解析记录后，以树形结构查看文档的元素层级关系，同时展示选中元素的完整详情
3. **元素级查询**：支持按元素类型、置信度范围、文本内容搜索等方式过滤和检索元素，满足精细化分析需求
4. **差异对比**：支持同一模板下不同训练任务的解析结果之间的差异对比（方案A），以及将解析结果与标准答案进行对比（方案B）

### 1.2 与现有功能的关系

本功能建立在已完成的模板训练功能基础之上，利用训练任务创建的 parse_record 数据，提供更深入的结果查看能力。

| 前置依赖 | 说明 |
|---------|------|
| train_file 表 | 训练文件上传记录 |
| train_task 表 | 训练任务记录 |
| parse_record 表 | 解析结果记录（由 Python 引擎写入） |
| parse_element 表 | 元素明细记录（已建表，待写入和查询） |

### 1.3 用户界面入口

用户在 TrainTask.vue 页面中完成训练后，点击训练任务右侧的"查看结果"入口进入训练结果详情页（TrainResultDetail.vue）。本功能对该页面进行全面重构升级。

### 2.2 模块一：parse_record 详情查看（结构树可视化展示）

**职责**：将 parse_record 中存储的 StructureTree JSON 解析为可视化的层级树，左侧展示元素结构树，右侧展示选中元素的完整详情。

**核心能力**：
- 将扁平 JSON 解析为树形结构数据
- 树节点按元素类型显示不同图标和颜色
- 点击树节点在右侧面板展示元素完整信息（内容、元数据、样式特征、置信度等）
- 支持树的展开/折叠

**涉及文件**：
- TrainResultDetail.vue（前端，大规模改造）
- ParseRecordController（后端，修改，增加详情接口）
- ParseRecordService（后端，修改，增加 JSON 解析方法）

### 2.3 模块二：parse_element 元素明细

**职责**：训练时将 StructureTree 中的每个元素拆解为独立的 parse_element 记录入库，前端提供元素级查询、筛选、搜索能力。

**核心能力**：
- Python 引擎写入 parse_record 时，同时将每个元素拆解为 parse_element 记录
- 按 record_id 查询某条解析记录的所有元素列表
- 按元素类型（elementType）筛选
- 按置信度范围筛选
- 按元素内容文本搜索（contentText LIKE）
- 分页返回结果

**涉及文件**：
- ParseElementController（后端，新增）
- ParseElementService（后端，新增）
- parse_element 表（已有，Python 引擎需补充写入逻辑）
- cli.py（Python，修改，增加元素拆解入库逻辑）

### 2.4 模块三：parse_diff_report 差异对比

**职责**：提供两种对比模式——任务间对比（方案A）和与标准答案对比（方案B）。

**核心能力**：
- **方案A — 任务间对比**：选中同一模板下的两条不同解析记录（来自不同训练任务），对比其元素差异
- **方案B — 标准答案对比**：上传标准答案 JSON，将解析结果与标准答案逐元素对比
- 差异展示：新增元素、缺失元素、类型变化、内容差异、置信度差异

**涉及文件**：
- ParseDiffReportController（后端，新增）
- ParseDiffReportService（后端，新增）
- ParseStandardAnswerController（后端，新增，方案B专用）
- ParseStandardAnswerService（后端，新增，方案B专用）
- parse_diff_report 表（已有，模型完善）
- parse_standard_answer 表（新建）

## 3. 数据模型设计

现有 parse_record 表已有字段满足需求，**无需新增字段**。但需要明确 `element_summary` 字段的存储格式，以便前端展示统计概览。

```json
{
  "totalElements": 45,
  "byType": {
    "heading": 8,
    "paragraph": 20,
    "table": 3,
    "image": 2,
    "list_ordered": 4,
    "list_unordered": 5,
    "code_block": 1,
    "block_quote": 2
  },
  "avgConfidence": 0.87,
  "minConfidence": 0.50,
  "maxConfidence": 1.00

```

### 3.2 parse_element 表设计（已有，补充说明）

现有 `ParseElement` 实体和 `parse_element` 表已建，字段定义如下：

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | AUTO_INCREMENT, PK | 主键 |
| record_id | BIGINT | NOT NULL, FK -> parse_record.id | 关联解析记录 |
| element_id | VARCHAR(100) | NOT NULL | 元素唯一标识符（如 "elem_0001"） |
| element_type | VARCHAR(50) | NOT NULL | 元素类型（heading/paragraph/table/等） |
| level | INT | NULLABLE | 层级（标题级别/列表嵌套层级） |
| content_text | LONGTEXT | NULLABLE | 元素文本内容（纯文本，不含格式） |
| confidence | DECIMAL(5,4) | NOT NULL, DEFAULT 0.0000 | 识别置信度 |
| parent_element_id | VARCHAR(100) | NULLABLE | 父级元素 ID，构建层级关系 |
| sort_order | INT | NOT NULL, DEFAULT 0 | 排序序号（同级中的顺序） |
| metadata | TEXT | NULLABLE | 元素元数据（JSON 格式，位置、样式名等） |
| style_features | TEXT | NULLABLE | 样式特征向量（JSON 格式，debug 用） |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引设计**：

| 索引名 | 字段 | 说明 |
|--------|------|------|

**外键约束**：

```sql

```

### 5.3 关键交互说明

#### 5.3.1 结构树视图交互

1. **初始加载**：进入页面后默认显示"结构树视图"Tab，自动加载当前选中解析记录的结构树
2. **树展开**：默认展开前两层（document 和一级标题），更深层级折叠
3. **节点选择**：点击树节点 → 右侧详情面板更新为该元素的详情
4. **节点图标**：不同类型的元素显示不同图标和颜色（详见 5.4）
5. **空状态**：结构树为空时显示空提示

#### 5.3.2 元素明细交互

1. **筛选联动**：修改任一筛选条件后，自动重新查询（或点击"查询"按钮）
2. **类型下拉**：从 `GET /api/parse-element/types` 获取当前记录的元素类型列表作为下拉选项
3. **置信度滑块**：使用 el-slider 范围选择，支持拖拽调节最小/最大值
4. **内容搜索**：关键字模糊搜索，输入后调用 `contentText LIKE` 查询
5. **查看树定位**：点击表格行的"查看树"按钮 → 切换到"结构树视图"Tab → 自动展开树并定位到对应节点

#### 5.3.3 差异对比交互

1. **方案A—任务间对比**：
   - 用户在两个下拉选择器中分别选择同一模板下的不同解析记录
   - 点击"对比"按钮发起请求
   - 对比完成后展示概览统计和差异列表
2. **方案B—标准答案对比**：
   - 用户先选择一个解析记录，再选择一个关联的标准答案
   - 标准答案需事先通过上传功能导入
   - 对比逻辑与方案A相同
3. **差异列表高亮**：
   - 新增项：绿色背景 + "+" 标记
   - 删除项：红色背景 + "-" 标记
   - 修改项：黄色背景 + "~" 标记
   - 类型变化：紫色背景 + "T" 标记

## 7. 技术选型

### 7.1 前端树组件选型

**选型结果：Element Plus Tree 组件（el-tree）**

| 选项 | 方案 | 评价 |
|------|------|------|
| Element Plus Tree | el-tree | **选中**。与现有技术栈一致，支持懒加载、自定义节点内容、拖拽、过滤 |
| vue-easytree | 第三方库 | 功能更丰富但引入额外依赖 |
| vxe-table tree | 第三方库 | 功能过于重量级，且与 Element Plus 样式不协调 |

**理由**：
- el-tree 已经随 Element Plus 存在，无需引入新依赖
- 支持 `render-content` 或 `scoped slot` 自定义节点渲染，可实现图标 + 颜色 + 内容摘要的混合展示
- 支持 `filter-node-method` 实现树节点搜索过滤
- 支持 `default-expanded-keys` 控制默认展开层级
- 若后续需要虚拟滚动（大量节点），可结合 `el-tree-v2` 使用

**树数据转换逻辑**：

```typescript
// structureTree JSON → el-tree data 转换
function convertToTreeData(structureTree: any): TreeNode[] {
  const root = structureTree?.root
  if (!root) return []
  
  function walk(node: any): TreeNode {
    return {
      id: node.id,
      label: getNodeLabel(node),    // 类型图标 + 内容摘要
      elementType: node.type,
      elementId: node.elementId || node.id,
      level: node.level,
      confidence: node.confidence,
      children: node.children?.map(walk) || []
    }
  }
  
  return [walk(root)]
}
```

### 7.2 JSON 展示选型

**选型结果：方案A — 结构化卡片展示 | 方案B — 预览区 JSON 展示**

对于元素详情，采用**结构化卡片展示**（非原始 JSON）作为默认视图，提供更好的可读性。同时提供"查看原始 JSON"的切换按钮，使用以下方案之一展示原始 JSON：

| 选项 | 方案 | 评价 |
|------|------|------|
| 结构化 el-descriptions + el-tag | 自定义渲染 | **选中（默认视图）**。与现有风格一致 |
| vue-json-pretty | 第三方库 | 较好，轻量，支持展开/折叠 |
| monaco-editor JSON 模式 | 重量级 IDE | 过于重量级，不适合当前场景 |

**结论**：
- **详情默认展示**：使用 Element Plus 的 `el-descriptions` + `el-tag` + 自定义样式，将元数据、样式特征等以结构化形式展示
- **JSON 原始查看**：引入 `vue-json-pretty`（约 10KB）作为轻量级 JSON 格式化展示组件，在"查看原始 JSON"按钮触发时显示

### 7.3 差异对比算法选型

**对比策略：基于 elementId 的元素级对齐对比**

```
输入: 记录A的元素列表 + 记录B的元素列表
输出: 差异变化列表

算法步骤:
1. 建立元素索引：以 elementId 为 key 构建 Map（记录A → MapA, 记录B → MapB）
2. 遍历 MapA 的 key：
   a. key 存在于 MapB → 对比内容/类型/置信度 → 标记为 "unchanged" 或 "changed"
   b. key 不存在于 MapB → 标记为 "removed"
3. 遍历 MapB 的 key：
   a. key 不存在于 MapA → 标记为 "added"
4. 计算统计指标：准确率 = unchanged / (totalA + totalB - unchanged)
```

**说明**：
- 适用于 elementId 在解析时由 Python 引擎保证一致性的场景（解析同一个文档时，相同结构位置生成相同的 elementId）
- 如果 elementId 不一致，退化策略为按 sort_order 逐位对齐对比（基于位置的对齐算法）
- 复杂度 O(n+m)，n 和 m 分别为两条记录的元素总数

## 8. 约束与风险

### 8.1 约束

| 约束项 | 说明 |
|--------|------|
| 树节点数量 | 单个文档元素总数可能超过 500 个，树组件需要支持虚拟滚动或分页展开 |
| StructureTree JSON 大小 | 大型文档（100页+）的 structureTree JSON 可能超过 10MB，API 传输需要注意压缩 |
| 差异对比效率 | 当元素总数超过 1000 时，差异对比操作应在后端同步完成，避免前端处理大量数据 |
| 标准答案文件格式 | 标准答案 JSON 必须与 Python 引擎输出的 StructureTree 格式一致 |
| 元素拆解时机 | parse_element 记录在 Python 引擎训练模式中写入，需要在训练完成后立即可查 |

### 8.2 风险与应对

| 风险 | 概率 | 影响 | 应对方案 |
|------|------|------|----------|
| StructureTree JSON 解析失败 | 中 | 高 | 前端使用 try-catch 包裹 JSON.parse，失败时显示"结构树解析失败"提示并提供原始 JSON 下载 |
| 树节点过多导致渲染卡顿 | 中 | 中 | 使用 el-tree-v2（虚拟滚动树），限制默认展开层数为 2 层 |
| parse_element 数据量过大 | 高 | 中 | 分页查询 + 按需加载，不一次性查询所有元素 |
| Python 引擎未写入 elementId | 中 | 高 | 在 Python 端确保 elementId 生成逻辑（层级索引路径如 "0.1.2"），缺失时前端用 index 替代 |
| 差异对比无变化（空结果） | 低 | 低 | 显示"两个记录完全相同"的提示 |
| 对比的两条记录元素数量悬殊 | 低 | 中 | 算法兼容不同数量级的对比，统计指标仍有效 |
| 标准答案格式不兼容 | 低 | 高 | 上传时进行严格的 JSON Schema 校验，拒绝无效格式 |

### 8.3 性能预期

| 指标 | 预期值 | 说明 |
|------|--------|------|
| 结构树渲染时间 | < 500ms | 200 个节点以内的树 |
| 元素明细分页查询 | < 100ms | 带索引的简单查询 |
| 差异对比（500元素以内） | < 500ms | 内存中 Map 对比 |
| 差异对比（1000元素以上） | < 2s | 元素数增加时线性增长 |
| 标准答案上传解析 | < 1s | JSON 文件校验和解析 |

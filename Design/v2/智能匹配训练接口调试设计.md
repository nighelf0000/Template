# 智能匹配训练接口调试设计文档

## 1. 概述

**目标**：调用 `POST /api/smart-match/1/train` 接口成功触发智能匹配训练，完成从创建任务到异步训练完成的全流程。

---

## 2. 接口调用链分析

### 2.1 完整调用链

```
HTTP POST /api/smart-match/{templateId}/train
    │ 请求参数：templateId=1, taskName(可选)
    │
    ▼
【Controller】SmartMatchController.startTraining()
    │ 接收参数，调用 Service
    │
    ▼
【Service】SmartMatchService.startTraining()
    │ 1. 检查同模板是否有 PENDING/RUNNING 任务 → 有则抛异常
    │ 2. 创建 SmartMatchTask 记录（status=PENDING）
    │ 3. 调用 SmartMatchTaskService.runTraining() — @Async 异步执行
    │ 4. 立即返回 task 对象（status=PENDING）
    │
    ▼
【Async】SmartMatchTaskService.runTraining()（异步线程）
    │
    ├── 阶段1：更新任务状态 → RUNNING（progress=5）
    │
    ├── 阶段2：查询 UploadFile（status=EXPORTED/ADJUSTED）
    │   └── 无文件 → 抛出异常"没有已处理的文件可用于训练"
    │
    ├── 阶段3：提取训练数据
    │   └── 解析 parsed_json → 按(matchType, matchLevel, styleRuleId)分组
    │   └── 无有效数据 → 抛出异常"未能从文件中提取有效的训练数据"
    │
    ├── 阶段4：构建训练 JSON → progress=50
    │
    ├── 阶段5：调用 Python 脚本（ProcessBuilder）
    │   ├── 将训练 JSON 写入 stdin
    │   └── 从 stdout 读取结果 JSON
    │   ├── 等待进程结束（超时 10 分钟）
    │   └── 检查退出码（非0 → 抛出异常）
    │
    ├── 阶段6：解析 Python 输出
    │   ├── success=false → 抛出异常（含 error 信息）
    │   └── rules 为空 → 抛出异常"训练未能生成有效规则"
    │
    ├── 阶段7：保存规则到 smart_match_rule 表
    │
    └── 阶段8：更新任务为 SUCCESS，progress=100
```

### 2.2 涉及的数据表

| 表名 | 用途 | 操作 |
|------|------|------|
| `template_config` | 模板配置 | 查询（外键约束） |
| `user_upload_file` | 训练数据源 | 查询（按 status 过滤） |
| `smart_match_task` | 训练任务记录 | 插入 + 多次更新 |
| `smart_match_rule` | 训练生成的规则 | 插入 |
| `template_rule` | 样式规则 | 查询（只读） |

### 2.3 涉及的外部依赖

| 依赖 | 用途 | 调用方式 |
|------|------|----------|
| MySQL 8.0+ | 持久化 | JDBC（MyBatis-Plus） |
| Python 3.10+ | 算法执行 | ProcessBuilder 子进程 |
| scikit-learn | TF-IDF 向量化 | Python import |
| numpy | 数值计算 | Python import |
| jieba | 中文分词 | Python import |

## 3. 潜在问题点分析

### 问题1：数据库就绪状态（最关键的先决条件）

**风险等级**：高

| 检查项 | 现状 | 可能的问题 |
|--------|------|-----------|
| MySQL 服务 | application.yml 配置 localhost:3306 | 可能未启动 |
| 数据库 template_db | 需手动或通过 init.sql 创建 | 可能不存在 |
| 表 smart_match_task | init.sql 中定义了 DDL | 可能未执行 |
| 表 smart_match_rule | init.sql 中定义了 DDL | 可能未执行 |
| 外键关联表 | 依赖于 template_config 表 | 需要先有模板数据 |

**判断依据**：
- `c:/AITeam/db/Configs.db` 是一个 16KB 的 SQLite 文件，不是 MySQL 数据库文件，说明项目使用 MySQL 作为主数据库。
- 需要手动执行 `init.sql` 来创建所有表结构。
- `template_config` 表中必须有 id=1 的记录才能满足外键约束。

### 问题2：训练数据准备

**风险等级**：高

`SmartMatchTaskService.runTraining()` 第68-70行查询条件：
```java
fileQuery.eq(UploadFile::getTemplateId, templateId)
        .in(UploadFile::getStatus, "EXPORTED", "ADJUSTED");
```

**可能的问题**：
- `user_upload_file` 表中没有 templateId=1 的记录
- 有记录但 status 不是 EXPORTED 或 ADJUSTED
- 有记录但 `parsed_json` 字段为空或格式无效
- `parsed_json` 中的 `matched_type` 全部为 UNKNOWN/SPECIAL（这些会被过滤掉）

### 问题3：Python 环境配置

**风险等级**：中

| 配置项 | 当前值 | 风险 |
|--------|--------|------|
| `python-path` | `python` | Windows 下可能需改为 `python`；Linux 下可能需改为 `python3`；也可能需要使用虚拟环境的完整路径 |
| `script-path` | `python/smart_train.py` | `resolveScriptPath()` 依赖 `user.dir` 系统属性，如果工作目录不是项目根目录会导致路径错误 |

**Python 依赖**（requirements.txt）：
```
scikit-learn>=1.3.0
numpy>=1.24.0
jieba>=0.42.0
```

如果缺少任一依赖，Python 脚本会在导入时失败并输出友好错误信息。

### 问题4：进程调用中的 Unicode/编码问题

**风险等级**：中

`ProcessBuilder` 在 Windows 上默认使用系统编码（GBK），而训练数据包含中文。当前代码使用 `StandardCharsets.UTF_8` 写入 stdin 和读取 stdout，但 Windows 下 Python 进程的默认编码可能是 GBK，导致中文数据在传输过程中出现乱码。

具体代码位置：
```java
// 写入 stdin
os.write(trainingJson.getBytes(StandardCharsets.UTF_8));

// 读取 stdout
resultJson = new String(is.readAllBytes(), StandardCharsets.UTF_8);
```

### 问题5：异步执行异常处理

**风险等级**：中

`@Async` 方法 `runTraining()` 内部有 try-catch 包裹全部逻辑，异常时更新任务为 FAILED 状态。但以下场景可能失败：
- `@Async` 注解不生效（如同类调用、未启用 `@EnableAsync`）—— 已通过 AsyncConfig 启用
- 线程池满——配置了 core=2, queue=10, max=4，正常情况下够用

### 问题6：Python 脚本自身错误

**风险等级**：低

`TfidfVectorizer` 初始化使用了已弃用的 `tokenizer` 参数（scikit-learn 1.3+ 推荐使用 `token_pattern` 或自定义分析器）：

```python
self.vectorizer = TfidfVectorizer(tokenizer=chinese_tokenizer, max_features=1000)
```

scikit-learn 1.3+ 中 `tokenizer` 参数仍然可用但有弃用警告，不会导致报错。但如果 scikit-learn 版本过高（1.6+），此参数可能被移除。

另外，`jieba.lcut` 在最新版本中对于某些分词场景可能会产生预期外的结果，但不会导致脚本崩溃。

### 问题7：超时设置

**风险等级**：低

超时时间默认 10 分钟，对于少量训练数据应该足够。但如果 `training_timeout_minutes` 被设置得过小，或训练数据量过大，可能导致超时。

### 问题8：同模板并发训练限制

**风险等级**：低

`startTraining()` 第48-53行检测同模板下是否有 PENDING/RUNNING 的任务。如果在之前有失败的任务（FAILED），不会影响新任务的创建。

## 4. 排查方案

### 排查方案一：准备数据库环境

**步骤**：
1. 确认 MySQL 服务正在运行（`net start mysql` 或任务管理器检查）
2. 使用 MySQL 客户端执行 `init.sql` 中的 DDL，创建数据库和表
3. 插入一条测试用的 `template_config` 记录（id=1, name='测试模板'）
4. 验证所有表已正确创建

### 排查方案二：准备训练数据

**步骤**：
1. 确认 `user_upload_file` 表中有 templateId=1 的数据
2. 确认这些数据的 status 为 EXPORTED 或 ADJUSTED
3. 检查 `parsed_json` 字段不为空且包含有效 JSON 数组
4. 验证 JSON 中包含 `matched_type`、`text`、`matched_level`、`rule_id` 等字段
5. 确保 `matched_type` 不全是 UNKNOWN 或 SPECIAL

如果没有现成的训练数据，需要通过以下流程准备：
- 通过文件上传接口上传一个 Word 文档
- 执行文档解析（模板识别），生成 parsed_json
- 执行导出操作，将文件状态改为 EXPORTED

### 排查方案三：确认 Python 环境

**步骤**：
1. 在终端执行 `python --version` 确认 Python 3.10+ 已安装
2. 执行 `pip install -r python/requirements.txt` 安装依赖
3. 执行 `python python/smart_train.py < test_input.json` 测试脚本是否能正常运行
4. 如使用虚拟环境，需在 application.yml 中配置虚拟环境的 Python 路径

### 排查方案四：编码问题修复

**方案 A**：在 ProcessBuilder 的环境变量中设置 `PYTHONIOENCODING=utf-8`：
```java
Map<String, String> env = pb.environment();
env.put("PYTHONIOENCODING", "utf-8");
```

**方案 B**：在 Python 脚本的 shebang 或 main() 中显式设置 stdin/stdout 编码：
```python
if sys.stdout.encoding != 'utf-8':
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
if sys.stdin.encoding != 'utf-8':
    sys.stdin = io.TextIOWrapper(sys.stdin.buffer, encoding='utf-8')
```

### 排查方案五：使用 curl/postman 测试接口

执行测试：
```bash
curl -X POST "http://localhost:8080/api/smart-match/1/train?taskName=测试训练"
```

预期返回（任务创建成功）：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "templateId": 1,
    "taskName": "测试训练",
    "status": "PENDING",
    "progress": 0,
    ...
  }
}
```

然后通过 `GET /api/smart-match/1/tasks` 轮询任务状态（PENDING → RUNNING → SUCCESS/FAILED）。

### 排查方案六：日志诊断

检查以下日志输出点：
- `SmartMatchController.startTraining()` 输入的 templateId 和 taskName
- `SmartMatchTaskService.runTraining()` 开始和结束日志
- Python 脚本的 stdout/stderr 输出
- 数据库操作异常（MyBatis 日志需要开启）

## 6. 测试验证方案

### 6.1 前置条件检查清单

- [x] MySQL 服务已启动（localhost:3306）
- [x] database `template_db` 已创建
- [x] 所有表已通过 `init.sql` 创建
- [x] `template_config` 中存在 id=1 的记录
- [x] `user_upload_file` 中存在至少一条 templateId=1, status=EXPORTED/ADJUSTED 的记录，且 parsed_json 有有效数据
- [x] Python 3.10+ 已安装，所需依赖已安装
- [x] Spring Boot 服务已启动（`http://localhost:8080` 可访问）

### 6.2 接口测试步骤

**第一步**：调用训练接口
```
POST http://localhost:8080/api/smart-match/1/train
```
检查返回：code=200，data.status="PENDING"

**第二步**：查看测试报告接口
```
GET http://localhost:8080/api/smart-match/1/tasks?page=1&size=10
```
检查返回：列表非空，最新创建的任务状态应为 PENDING→RUNNING→SUCCESS/FAILED

**第三步**：查看任务详情
```
GET http://localhost:8080/api/smart-match/1/tasks/{taskId}
```
检查返回：status、progress、errorMessage（如果失败）

**第四步**：验证生成的规则
```
GET http://localhost:8080/api/smart-match/1/rules?page=1&size=10
```
如果训练成功，应能查看到生成的规则列表

### 6.3 错误场景测试

| 场景 | 预期结果 |
|------|----------|
| 无训练数据 | 任务状态 FAILED，errorMessage 含提示"没有已处理的文件" |
| Python 未安装 | 任务状态 FAILED，errorMessage 含 Python 依赖缺失提示 |
| Python 脚本出错 | 任务状态 FAILED，errorMessage 含脚本错误信息 |
| 同模板并发训练 | 第二次调用直接抛出异常，不创建新任务 |

### 6.4 判定标准

接口调用成功 = 满足以下条件之一：
1. **完整成功**：`POST /api/smart-match/1/train` 返回 200，且稍后查询任务状态为 SUCCESS
2. **任务创建成功**：返回 200 且任务状态为 PENDING（异步执行部分可能受环境限制，但接口本身正常工作）

## 7. 常见失败场景排查速查表

| 现象 | 可能原因 | 解决方案 |
|------|----------|----------|
| 接口返回 500 / 数据库错误 | 表不存在或 MySQL 未启动 | 执行 init.sql，检查 MySQL 服务 |
| 任务状态 FAILED，"没有已处理的文件" | UploadFile 表无符合条件的数据 | 先上传并解析文件，执行导出操作 |
| 任务状态 FAILED，"未能提取有效训练数据" | parsed_json 格式不符或 matched_type 全部为 UNKNOWN | 检查 parsed_json 数据结构 |
| 任务状态 FAILED，"Python 依赖缺失" | Python 依赖未安装 | `pip install -r requirements.txt` |
| 任务状态 FAILED，"训练脚本执行失败" | Python 路径或脚本路径错误 | 检查 application.yml 配置 |
| 任务状态 FAILED，"训练超时" | 训练数据量大或 Python 阻塞 | 增大 timeout，检查 Python 进程 |
| 接口直接返回 500 | 外键约束失败（templateId 不存在） | 检查 template_config 表是否有 id=1 |

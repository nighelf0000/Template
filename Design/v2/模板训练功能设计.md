## 1. 概述

**项目目标**：构建一个基于规则引擎的 Word 文档结构识别工具，将 .docx 文件解析为带层级关系和元数据的 JSON 结构树；并在此基础上新增"模板训练"功能，支持用户上传训练文档集合，批量执行文档结构识别，将识别结果持久化存储。

系统由两个子系统组成：

| 子系统 | 技术栈 | 职责 |
|--------|--------|------|
| doc-struct（Python 引擎） | Python 3.10+ / python-docx / lxml | Word 文档结构识别，输出 StructureTree JSON |
| Template（Java + Vue） | Spring Boot 3.2.5 / MyBatis-Plus 3.5.6 / Vue 3 + Element Plus | 文件管理、模板配置、训练任务管理、解析结果展示 |

### 2.2 文档解析层

#### (1) 文档加载器 (DocumentLoader)

| 项目 | 内容 |
|------|------|
| **职责** | 接收 .docx 文件路径，校验文件有效性，加载文档到内存，提供统一的文档对象访问接口 |
| **输入** | .docx 文件路径 |
| **输出** | 内部统一的 Document 对象 |
| **关键能力** | 文件格式校验、损坏检测、大文件流式加载、编码检测 |

#### (2) 样式分析器 (StyleAnalyzer)

| 项目 | 内容 |
|------|------|
| **职责** | 读取 Word 文档中所有段落的样式信息（样式名称、字体、字号、加粗、颜色、缩进、行距等），建立样式索引 |
| **输入** | Document 对象 |
| **输出** | 样式索引表 (StyleIndex)：段落 ID → 样式特征向量 |
| **关键能力** | 内置样式 + 自定义样式解析、样式继承链解析、中文字体/英文字体区分 |

#### (3) XML 解析器 (XmlParser)

| 项目 | 内容 |
|------|------|
| **职责** | 直接访问 docx 的 XML 底层 (word/document.xml)，获取 python-docx 未暴露的元信息（分页符、分节符、批注、脚注尾注的引用标记等） |
| **输入** | Document 对象（底层 zip 包） |
| **输出** | 补充元素列表（分页符、批注引用、脚注引用等） |
| **关键能力** | XPath 查询、XML 命名空间处理、与 python-docx 对象模型的映射 |

### 2.3 规则引擎层

#### (4) 规则仓库 (RuleRepository)

| 项目 | 内容 |
|------|------|
| **职责** | 管理规则集（规则组），支持规则的加载、保存、增删改查。规则以 JSON/YAML 文件形式存储在本地 |
| **输入** | 规则文件路径 / 规则集名称 |
| **输出** | 规则集对象 (RuleSet) |
| **关键能力** | 多规则集管理、规则优先级排序、规则冲突检测 |

#### (5) 规则解析器 (RuleParser)

| 项目 | 内容 |
|------|------|
| **职责** | 将规则定义文件（JSON/YAML）解析为内存中的规则对象，校验规则语法的合法性 |
| **输入** | 原始规则定义（字典形式或文件路径） |
| **输出** | Rule 对象列表 |
| **关键能力** | 规则语法校验、条件表达式解析、规则版本兼容性检查 |

#### (6) 规则执行器 (RuleEngine)

| 项目 | 内容 |
|------|------|
| **职责** | 接收段落/元素及其样式特征，遍历规则集进行匹配，返回分类结果。规则引擎是系统的核心决策组件 |
| **输入** | 样式特征向量 (StyleFeature) + 规则集 (RuleSet) |
| **输出** | 分类结果 (ClassificationResult)：元素类型 + 置信度 + 匹配的规则 ID |
| **关键能力** | 顺序匹配（优先级排序）、首匹配/最佳匹配策略、规则条件组合（AND/OR/NOT）、缺失特征降级处理 |

### 2.4 核心处理层

#### (7) 内容提取器 (ContentExtractor)

| 项目 | 内容 |
|------|------|
| **职责** | 根据分类结果，提取各类元素的具体内容。不同类型提取逻辑不同（表格提取行列数据、图片提取尺寸/路径、列表提取层级/序号等） |
| **输入** | 分类结果 + 原始元素句柄 |
| **输出** | 结构化内容字典 |
| **关键能力** | 图片提取（内嵌图片 + 绘制对象）、表格合并单元格处理、列表多层级解析、代码块保持缩进和换行 |

#### (8) 层级构建器 (HierarchyBuilder)

| 项目 | 内容 |
|------|------|
| **职责** | 将扁平的元素列表按标题层级构建为嵌套的 JSON 树结构。处理章节嵌套、多级标题、无标题段落归属等问题 |
| **输入** | 元素列表 (List[DocumentElement]) |
| **输出** | 嵌套的结构树 (StructureTree) |
| **关键能力** | 标题级别驱动的树构建、目录项特殊处理、正文段落归属到最近标题、跨章节元素的独立分支处理 |

#### (9) 元数据提取器 (MetadataExtractor)

| 项目 | 内容 |
|------|------|
| **职责** | 提取文档级和元素级的元数据：页码、位置坐标（相对段落顺序）、创建时间、作者等 |
| **输入** | Document 对象 + 元素列表 |
| **输出** | 元数据字典（文档级 + 元素级） |
| **关键能力** | 分页信息估算（按行距/字号推算）、页面设置读取、文档属性读取 |

#### (10) 分类器引擎 (ClassifierEngine)

| 项目 | 内容 |
|------|------|
| **职责** | 编排整个识别流程：对每个段落/元素，依次调用样式分析 → 规则匹配 → 内容提取 → 后处理纠偏 |
| **输入** | 原始 Document 对象 |
| **输出** | 已分类的元素列表 |
| **关键能力** | 多阶段分类（粗分类 → 细分类 → 上下文矫正）、上下文矫正（如连续相同样式的段落合并为一个正文块）、后处理规则（正则修正） |

### 2.5 交付层

#### (11) Python SDK (DocumentStructureSDK)

| 项目 | 内容 |
|------|------|
| **职责** | 面向开发者的 Python API，封装核心识别流程，提供便捷的调用接口 |
| **输入** | .docx 文件路径（或文件对象）+ 可选参数（规则集名称、输出格式选项等） |
| **输出** | StructureTree 对象（可序列化为 JSON） |
| **主要方法** | `recognize(filepath, ruleset=None, options=None) → StructureTree` |

#### (12) CLI 工具 (doc-struct)

| 项目 | 内容 |
|------|------|
| **职责** | 命令行入口，封装 SDK 调用，支持文件输入/输出重定向 |
| **输入** | 命令行参数 |
| **输出** | JSON 到 stdout 或文件 |
| **命令示例** | `doc-struct input.docx -o output.json` `doc-struct input.docx --ruleset academic` |

### 3.1 训练文件管理模块（TrainFileModule）

| 项目 | 内容 |
|------|------|
| **职责** | 管理模板训练用的 Word 文档的上传、列表查询、删除，提供原始文件内容下载供 Python 引擎调用 |
| **输入** | 用户上传的 .docx 文件 + 模板 ID |
| **输出** | 训练文件记录（入库）、原始文件字节流（供 Python 引擎） |
| **所在层** | Controller + Service + Entity/Mapper |
| **关键能力** | 文件格式校验（仅 .docx）、大文件 BLOB 存储、按模板维度分组管理 |

### 3.2 训练任务管理模块（TrainTaskModule）

| 项目 | 内容 |
|------|------|
| **职责** | 创建训练任务、启动 Python 引擎批量识别、管理任务生命周期（状态、进度、错误），供前端查看任务列表和详情 |
| **输入** | 模板 ID（创建任务时） |
| **输出** | 训练任务记录（入库）、Python 子进程调用、培训完成后关联的 parse_record 列表 |
| **所在层** | Controller + Service + Entity/Mapper |
| **关键能力** | 并发控制（同模板不允许并行训练）、进度计算（按文件数百分比）、超时控制、Python 子进程生命周期管理 |

### 3.3 Python 引擎训练模块（PythonEngineTrainModule）

| 项目 | 内容 |
|------|------|
| **职责** | 在 Python doc-struct 引擎中新增 `--mode train` 模式，实现批量文件识别、进度回调、结果存储 |
| **输入** | `--train-id` 训练任务 ID + `--api-url` 后端地址 |
| **输出** | 每个文件的 parse_record 记录 + 训练状态更新 |
| **所在层** | doc-struct CLI（Python） |
| **关键能力** | 通过 API 获取文件列表和原始内容、逐个文件调用现有识别流程、每完成一个文件回调进度、全部完成后更新训练状态 |

### 3.4 前端展示模块（FrontendTrainModule）

| 项目 | 内容 |
|------|------|
| **职责** | 提供训练文件上传管理、训练任务生命周期管理、识别结果查看的交互界面 |
| **输入** | 用户操作（上传文件、创建任务、查看结果） |
| **输出** | 页面展示 + API 调用 |
| **所在层** | Vue 3 前端 |
| **关键能力** | 文件上传（大文件进度提示）、训练任务进度轮询显示、识别结果列表展示、侧边栏独立菜单 |

## 4. 接口定义

### 4.1 Python 引擎模块间内部接口

#### 接口 I1：文档加载 → 样式分析 / XML 解析

```
DocumentLoader.load(path: str) → docx.Document
```

#### 接口 I2：样式分析 → 分类器引擎

```
StyleAnalyzer.analyze(document: docx.Document) → StyleIndex
StyleIndex = Dict[str, StyleFeature]

StyleFeature = {
    "style_name": str,           # Word 样式名称（如 "Heading 1", "Normal"）
    "font_name": str,            # 字体名称
    "font_size": float,          # 字号（磅）
```

### 4.4 Python 引擎训练模式 CLI（新增）

在现有 CLI 基础上新增两种运行模式：

#### 单文件识别模式（现有，不变）

```bash
python -m docstruct --file-id ID --api-url URL [--ruleset NAME] [--template-id ID]
```

#### 批量训练模式（新增）

```bash
python -m docstruct --mode train --train-id TASK_ID --api-url URL [--ruleset NAME]
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `--mode` | String | 否 | 运行模式：`train`（批量训练）或 `file`（单文件识别）。默认 `file` |
| `--train-id` | Long | 是（train 模式下） | 训练任务 ID，用于获取文件列表和回调进度 |
| `--api-url` | String | 是 | Template 后端 API 基地址（如 `http://localhost:8080`） |
| `--ruleset` | String | 否 | 规则集名称（默认 `default`） |
| `--debug` | Boolean | 否 | 调试模式 |

**训练模式执行流程（Python 端）**：

```
1. 解析命令行参数，判定 --mode=train
2. GET {apiUrl}/api/train-task/{trainId}         → 获取训练任务信息（含模板ID）
3. 从训练任务信息中获取 templateId
4. GET {apiUrl}/api/train-file/list?templateId=X → 获取所有训练文件列表
5. 如果文件列表为空，直接更新状态为 FAILED 并退出
6. 更新状态为 RUNNING，progress=0

7. 遍历文件列表，对每个文件：
   a. GET {apiUrl}/api/train-file/{fileId}/raw   → 下载 .docx 字节流
   b. 调用 doc-struct 核心识别流程               → 得到 StructureTree JSON
   c. POST {apiUrl}/api/parse-record              → 保存解析结果至 parse_record 表
      Body: {
        "templateId": trainTask.templateId,
        "sourceFile": file.originalName,
        "sourceChecksum": "SHA256(...)",
        "fileSize": file.originalSize,
        "structureTree": {...},
        ...
      }
   d. 计算进度百分比 = 当前文件序号 / 总文件数 * 100
   e. PUT {apiUrl}/api/train-task/{trainId}/progress
      Body: {
        "progress": 计算后的百分比,
        "currentFile": 当前序号,
        "totalFiles": 总文件数,
        "message": "正在处理: {文件名}"
      }

8. 全部完成 → PUT {apiUrl}/api/train-task/{trainId}/status
   Body: { "status": "SUCCESS", "errorMessage": null }

   任一文件失败（非致命）→ 继续处理其他文件，最后在 status 回调中报告部分失败
   致命错误（网络不通等）→ PUT status=FAILED，退出
```

### 5.2 规则配置数据模型

规则以 YAML 格式存储，易于手工编辑。

```yaml
# rulesets/default.yaml
name: default
version: "1.0"
description: 通用文档结构识别规则集

rules:
  - id: heading_1
    priority: 100
    element_type: heading
    level: 1
    description: "样式名称为 Heading 1 或大纲级别为 1"
    match_strategy: any
    conditions:
      - field: style_name
        operator: eq
        value: "heading 1"
      - field: outline_level
        operator: eq
        value: 1
    confidence: 0.95

  - id: heading_2
    priority: 99
    element_type: heading
    level: 2
    match_strategy: any
    conditions:
      - field: style_name
        operator: eq
        value: "heading 2"
      - field: outline_level
        operator: eq
        value: 2
    confidence: 0.95

  - id: code_block
    priority: 60
    element_type: code_block
    match_strategy: all
    conditions:
      - field: font_name
        operator: in
        value: ["Courier New", "Consolas", "Source Code Pro", "JetBrains Mono", "Fira Code"]
    confidence: 0.7

  # 兜底规则
  - id: fallback_paragraph
    priority: 0
    element_type: paragraph
    match_strategy: any
    conditions: []
    confidence: 0.5
```

## 7. 文件上传与Python引擎集成

### 7.1 集成方案概述

Python doc-struct 引擎**独立于 Template Java 项目**，通过 ProcessBuilder 子进程方式调用。关键设计决策：

> **Java 不写临时文件。Python 通过 REST API 自行获取文件内容和回存解析结果。**

Java 只传递 `fileId`（或 `trainId`），Python 引擎通过 API 从数据库获取 `.docx` 内容，解析完成后通过 API 存回 `parse_record` 表。

### 7.2 完整数据流（训练模式）

```
┌──────────────────────────────────────────────────────────────────┐
│  Step 1: 上传训练文件                                              │
│  Frontend → POST /api/train-file/upload                          │
│  → TrainFileService.save() 存入 train_file (LONGBLOB)            │
│  → 返回 fileId, 状态: UPLOADED                                    │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  Step 2: 创建训练任务                                              │
│  Frontend → POST /api/train-task/start                           │
│  → TrainTaskService.start()                                      │
│    ├─ 检查同模板是否有运行中任务                                    │
│    ├─ 查询模板下 UPLOADED 文件列表                                 │
│    ├─ INSERT train_task (PENDING)                                │
│    ├─ UPDATE status=RUNNING, totalFiles=N                        │
│    └─ 异步调用 TrainTaskRunnerService                             │
│        └─ ProcessBuilder 启动 Python 子进程                        │
│            python -m docstruct                                    │
│              --mode train                                         │
│              --train-id 1                                         │
│              --api-url http://localhost:8080                      │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│  Step 3: Python 引擎自主完成批量识别+存储                           │
│                                                                  │
│  ① 通过 API 获取任务信息和文件列表:                                 │
│     GET {apiUrl}/api/train-task/{trainId}                        │
│     GET {apiUrl}/api/train-file/list?templateId=X                │
│                                                                  │
│  ② 对每个文件循环:                                                 │
│     a. GET {apiUrl}/api/train-file/{fileId}/raw → .docx 字节     │
│     b. 执行核心识别流程:                                           │
│        DocumentLoader → StyleAnalyzer → RuleEngine               │
│        → ContentExtractor → HierarchyBuilder                     │
│        → StructureTree (JSON)                                    │
│     c. POST {apiUrl}/api/parse-record → 存回 MySQL               │
│     d. PUT {apiUrl}/api/train-task/{trainId}/progress → 更新进度  │
│                                                                  │
│  ③ 全部完成:                                                      │
│     PUT {apiUrl}/api/train-task/{trainId}/status → SUCCESS       │
│     输出结果 JSON 到 stdout (供 Java 读取)                         │
└──────────────────────────────────────────────────────────────────┘
```

**核心原则**：Python 引擎不直接访问 MySQL 数据库，所有数据交互通过 Java REST API 完成。

### 7.3 Java 端实现要点

#### TrainTaskRunnerService

```java
@Service
public class TrainTaskRunnerService {

    @Value("${template.train.python-path:python}")
    private String pythonPath;

    @Value("${template.train.timeout-minutes:30}")
    private int timeoutMinutes;

    @Value("${template.train.api-base-url:http://localhost:8080}")
    private String apiBaseUrl;

    /**
     * 调用 Python doc-struct 引擎执行批量训练。
     * Java 仅传递 --train-id 和 --api-url，Python 自行获取文件列表和回存结果。
     */
    public Map<String, Object> runTraining(Long trainId) {
        List<String> cmd = new ArrayList<>();
        cmd.add(pythonPath);
        cmd.add("-m");
        cmd.add("docstruct");
        cmd.add("--mode");
        cmd.add("train");
        cmd.add("--train-id");
        cmd.add(trainId.toString());
        cmd.add("--api-url");
        cmd.add(apiBaseUrl);

        ProcessBuilder pb = new ProcessBuilder(cmd);
        Process process = pb.start();

        // stdout/stderr 异步读取、超时控制
        // (复用与现有 SmartMatchTaskService 一致的模式)
    }
}
```

### 8.2 Python 引擎内部线程模型（Java 端）

为避免 stdin/stdout/stderr 管道死锁，TrainTaskRunnerService 采用异步读取模式：

```
┌─ Java 主线程 ────────────────────────────────────────────┐
│  TrainTaskRunnerService.runTraining()                     │
│    ├─ ProcessBuilder.start() → process                    │
│    ├─ 启动 stdout 读取线程                                 │
│    ├─ 启动 stderr 读取线程                                 │
│    ├─ process.waitFor(timeout, TimeUnit.MINUTES)          │
│    ├─ stdoutReader.join() 等待读取完成                      │
│    ├─ stderrReader.join()                                  │
│    ├─ 解析 stdout JSON 输出                                │
│    └─ 更新任务状态                                        │
└──────────────────────────────────────────────────────────┘

┌─ stdout 读取线程 ─────────────────────────────────────────┐
│  读取 stdout → 写入 ByteArrayOutputStream                  │
│  防止 stdout 管道缓冲区满导致阻塞                            │
└──────────────────────────────────────────────────────────┘

┌─ stderr 读取线程 ─────────────────────────────────────────┐
│  读取 stderr → 写入 ByteArrayOutputStream                  │
│  防止 stderr 管道缓冲区满导致阻塞                            │
└──────────────────────────────────────────────────────────┘
```

## 10. 约束与风险

### 10.1 Python 引擎已知限制

| 限制项 | 说明 |
|--------|------|
| 仅支持 .docx 格式 | 不支持 .doc（旧版 Word 格式）和扫描 PDF |
| 不支持扫描件 | .docx 中的嵌入式扫描图片无法提取文字结构 |
| 分页估算非精确 | Word 的分页取决于打印机驱动和渲染引擎 |
| 表格复杂度受限 | 合并单元格复杂度过高的表格解析可能不完整 |
| 页眉页脚识别受限 | 只识别每节首页的页眉页脚 |

### 10.2 Python 引擎风险与应对

| 风险 | 概率 | 影响 | 应对方案 |
|------|------|------|----------|
| 中文文档样式不规范 | 高 | 中 | 规则引擎提供补丁机制，兜底规则保证至少识别为"正文" |
| 自定义样式覆盖官方样式 | 中 | 高 | 优先识别官方样式名称，再按字体特征启发式匹配 |
| 大文档（100页+）性能 | 中 | 低 | 单文档处理、无严格时间要求 |
| 不同语言版本 Word 样式名不同 | 中 | 中 | 规则集中包含样式名别名映射 |
| 规则配置错误导致误识别 | 低 | 高 | 规则校验机制 + 版本管理可回滚 |

### 10.3 训练功能已知限制

| 限制项 | 说明 |
|--------|------|
| 仅支持 .docx 格式 | 训练文档必须是 .docx 格式 |
| 单次训练文件数 | 建议不超过 50 个 |
| 单文件大小上限 | 50MB（与 Spring 配置一致） |
| 相同文件重复上传 | 不做内容去重（SHA256 校验），可多次上传 |
| 进度估算精度 | 进度按文件数线性计算，大小文件处理时间不同 |

### 10.4 训练功能风险与应对

| 风险 | 概率 | 影响 | 应对方案 |
|------|------|------|----------|
| Python 引擎执行时间过长 | 中 | 中 | 超时默认 30 分钟，超时后强制终止并标记 FAILED |
| Python 进程内存溢出 | 低 | 高 | 逐个文件处理，处理完释放内存 |
| 训练过程中服务重启 | 低 | 中 | `@PostConstruct` 重置 PENDING/RUNNING 任务为 FAILED |
| 进度回调接口被外部恶意调用 | 低 | 中 | 内部 Token 认证（`X-Internal-Token` 请求头） |
| 文件内容占用大量数据库空间 | 中 | 低 | LONGBLOB 单条最大 4GB，定期清理 |
| 同模板误触多次训练 | 低 | 中 | 创建前检查同模板是否有 PENDING/RUNNING 任务 |

### 10.5 性能预期

| 指标 | 预期值 | 说明 |
|------|--------|------|
| 单文档处理时间 | 1-5 秒 | 50-100 页普通文档 |
| 10 个文件训练任务总时间 | 10-60 秒 | 串行处理，含网络传输 |
| 进度刷新延迟 | 1-3 秒 | 文件处理完成到前端更新（HTTP 回调 + 轮询间隔） |
| 并发训练任务数 | 同一模板仅 1 个 | 通过并发检查控制 |

### F. 识别流程伪代码

```
function recognize(filepath):
    document = DocumentLoader.load(filepath)
    features = StyleAnalyzer.analyze(document)
    supplement = XmlParser.parse(document)
    
    flat_elements = []
    
    // 阶段 1：段落分类
    for paragraph in document.paragraphs:
        feature = features[paragraph.id]
        result = RuleEngine.classify(feature, active_ruleset)
        content = ContentExtractor.extract(result.type, paragraph, document)
        
        flat_elements.append(DocumentElement(
            type=result.type,
            level=result.level,
            content=content,
            confidence=result.confidence,
        ))
    
    // 阶段 2：补充非段落元素（表格、图片、分页符等）
    for table in document.tables:
        flat_elements.append(extract_table_element(table))
    
    for elem in supplement:
        flat_elements.append(elem)
    
    // 阶段 3：上下文矫正
    corrected = ClassifierEngine.correct_context(flat_elements)
    
    // 阶段 4：构建层级树
    tree = HierarchyBuilder.build(corrected)
    
    // 阶段 5：附加元数据
    tree.metadata = MetadataExtractor.extract(document, corrected)
    
    return tree
```

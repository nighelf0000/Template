# 训练任务同步/异步模式切换设计

## 概述

为智能匹配训练接口增加同步执行能力，通过配置文件开关控制训练模式（默认异步），满足调试场景下需要实时获取训练结果并查看完整日志的需求。

---

## 方案设计

### 配置项驱动

在 `application.yml` 的 `template.smart-match` 节点下新增 `async` 配置项：

```yaml
template:
  smart-match:
    async: true                    # 新增：true=异步(默认) false=同步
    python-path: python
    script-path: python/smart_train.py
    training-timeout-minutes: 10
    batch-size: 50
```

- `async: true`（默认值）— 保持现有行为，异步执行训练
- `async: false` — 同步执行训练，请求线程等待训练完成并返回最终结果

**生效范围**：全局生效，所有训练任务共用此配置。

### 执行流程

#### 异步模式（默认，现有行为不变）

```
客户端 POST /api/smart-match/{templateId}/train
  └→ SmartMatchController.startTraining()
      └→ SmartMatchService.startTraining()  ← @Transactional
          ├── 检查/创建任务记录
          └── smartMatchTaskService.runTrainingAsync()  ← @Async
               └── 新线程执行训练逻辑
          ← 立即返回任务记录（状态: PENDING）
```

#### 同步模式（新增）

```
客户端 POST /api/smart-match/{templateId}/train
  └→ SmartMatchController.startTraining()
      └→ SmartMatchService.startTraining()  ← @Transactional（同步模式下共用事务）
          ├── 检查/创建任务记录
          └── smartMatchTaskService.runTraining()  ← 直接调用，无 @Async
               └── 当前线程执行完整训练逻辑
          ← 等待训练完成后返回任务记录（状态: SUCCESS/FAILED）
```

### 关键技术决策

#### 1. 移除 `@Async` 注解，分离同步/异步入口

当前 `SmartMatchTaskService.runTraining()` 方法上标注了 `@Async("smartMatchTaskExecutor")`，通过 Spring AOP 代理使其始终在独立线程执行。

要实现同步调用，需要提供一个不带 `@Async` 的方法。采取以下重构策略：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 从 `runTraining()` 上移除 `@Async` 注解 | 使其成为纯同步方法 |
| 2 | 新增 `runTrainingAsync()` 方法，标注 `@Async("smartMatchTaskExecutor")` | 内部直接调用 `runTraining()` 委托执行 |
| 3 | `SmartMatchService` 根据配置选择调用路径 | `async=true` → `runTrainingAsync()`；`async=false` → `runTraining()` |

```
SmartMatchTaskService
├── runTraining(templateId, taskId)           ← 核心逻辑，无 @Async
└── runTrainingAsync(templateId, taskId)      ← @Async，委托给 runTraining()
```

#### 2. 配置注入

两个 Service 均需要读取 `async` 配置值：

- **SmartMatchTaskService**：新增 `@Value("${template.smart-match.async:true}")` 字段 `asyncEnabled`
- **SmartMatchService**：新增 `@Value("${template.smart-match.async:true}")` 字段 `asyncEnabled`

#### 3. 同步模式下的事务行为

- 同步模式调用时，训练逻辑运行在 `SmartMatchService.startTraining()` 的 `@Transactional` 事务上下文中
- 训练过程中的所有数据库操作（状态更新、进度写入、规则插入）均参与同一事务
- 若训练成功：事务提交，任务状态为 `SUCCESS`
- 若训练失败抛出异常：事务回滚，包括最开始的 `INSERT` 任务记录一并撤销
- **已知影响**：同步模式下中间进度变更（5%、15%、30%...）在事务提交前不可见，只有最终结果可见

   - 原第 49 行 `@Async("smartMatchTaskExecutor")` → 删除

2. **新增** `asyncEnabled` 配置字段：

   ```java

       runTraining(templateId, taskId);
   }
   ```

### 文件 3：`SmartMatchService.java`

**路径**：`Projects/Template/src/main/java/com/template/service/SmartMatchService.java`

**改动**：

1. **新增** `asyncEnabled` 配置字段：
   ```java
   @Value("${template.smart-match.async:true}")
   private boolean asyncEnabled;
   ```

2. **修改** `startTraining()` 方法中的调用逻辑（第 66 行附近）：
   ```java
   // 原代码（始终异步）：
   // smartMatchTaskService.runTraining(templateId, task.getId());

   // 新代码（根据配置切换）：

   }
   ```

## 约束与风险

### 已知约束

| 约束项 | 说明 |
|--------|------|
| **全局生效** | 配置项为全局开关，无法按单次请求独立控制。如需精细化控制，可后续扩展为请求参数覆盖 |
| **同步超时** | 同步模式下训练时间取决于 Python 脚本执行耗时。当前 `training-timeout-minutes` 默认 10 分钟，同步模式下 HTTP 连接可能因等待过长而超时，建议同步模式仅用于小数据量调试 |
| **事务回滚** | 同步模式下训练失败会导致事务回滚，包括任务创建记录被撤销。这是用户选择的"共用事务"行为的自然结果 |
| **进度不可见** | 同步模式下的中间进度（5%、15%、30%...）在事务提交前不可见，客户端只能看到最终结果 |
| **请求线程阻塞** | 同步模式下 Web 容器的请求线程会被训练任务阻塞，注意线程池耗尽风险，不建议在生产环境启用同步模式 |

### 风险及应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 同步模式生产误开启 | 请求线程长时间阻塞，可能导致 Tomcat 线程池耗尽 | 通过代码注释和 CR 流程警示；可考虑增加运行环境检测 |
| `@Async` 移除后漏改调用方 | 其他调用 `runTraining()` 的地方从异步变为同步 | 经代码搜索确认，`runTraining()` 仅在 `SmartMatchService.startTraining()` 中被调用，无其他调用方 |
| 同步模式异常未处理 | 未捕获异常上抛至 Controller，返回 500 | `runTraining()` 内部已有 try-catch，异常会设置任务状态为 FAILED 并记录 errorMessage，然后继续抛出；Controller 层返回异常响应 |

### 回归验证点

发布后需验证以下场景确保不破坏现有功能：

1. 配置 `async: true`（默认值），触发训练 → 确认异步执行
2. 配置 `async: false`，触发训练 → 确认同步执行、等待完成后返回
3. 同步模式下训练成功 → 确认任务状态为 SUCCESS，规则已生成
4. 同步模式下训练失败 → 确认事务回滚、任务记录被撤销
5. 同步模式下超时场景 → 确认异常处理正常

## 二、需求1：训练完成后关键词去重更新

### 2.1 核心语义

训练结束后，Python 脚本返回的每一条规则在入库前，先按 **keywords（集合匹配）** 在**同一个 templateId 内**查重：

- **重复**：将新规则的 keywords 与已存在规则的 keywords 各自按 `,` 拆分、trim 后转为 `Set<String>`，两个集合 `equals` 即为重复（不关心顺序）。
- **无重复**：执行 `insert`，保持现有行为。
- **有重复**：从所有匹配的已有规则中，选出 **`isActive=1` 且 `matchOrder` 最小**的那一条，对其执行 `updateById`（更新非标识性字段），**不执行 insert**。

### 2.2 更新字段清单

| 字段 | 是否更新 | 说明 |
|------|----------|------|
| `templateId` | 不更新 | 标识性字段，新旧一致 |
| `matchType` | 不更新 | 标识性字段，新旧一致 |
| `matchLevel` | 不更新 | 标识性字段，新旧一致 |
| `styleRuleId` | 不更新 | 标识性字段，新旧一致 |
| `keywords` | 不更新 | 标识性字段，新旧一致 |
| `featureVector` | **更新** | Python 新训练的向量更优 |
| `threshold` | **更新** | 使用新训练的阈值 |
| `ruleName` | **更新** | 使用新训练的规则名称 |
| `taskId` | **更新** | 关联本次训练任务 ID |
| `matchOrder` | **更新** | 反映本次训练的新排序 |
| `updatedAt` | **更新** | 设为当前时间 |
| `isActive` | **不更新** | 保留原规则的活动状态（用户可能已手动关闭） |
| `id` | 不更新 | 主键不变 |
| `createdAt` | 不更新 | 保留首次创建时间 |

### 2.3 多规则冲突处理

假设同一组 keywords 命中了多条已有规则（例如用户手动复制了规则），则：

1. 在命中结果集中，过滤出 `isActive = 1` 的规则；
2. 如果存在至少一条激活的规则，取其中 `matchOrder` 最小的那条；
3. 如果没有任何激活的规则，则取所有命中结果中 `matchOrder` 最小的那条；
4. 对该选中的规则执行 `updateById`。

### 2.4 修改位置：SmartMatchTaskService.java

**目标方法**：`runTraining(Long templateId, Long taskId)`  
**替换段落**：第239-275行（从 `// 7. 保存规则到数据库` 到 `smartMatchRuleMapper.insert(rule);` 的循环）

#### 2.4.1 新增辅助方法

在 `SmartMatchTaskService` 类中新增一个私有方法，用于将 keywords 字符串转为用于比较的 `Set<String>`：

```java
/**
 * 将 keywords 字符串按逗号拆分、trim 后转为 Set，用于集合匹配比较
 */
private Set<String> parseKeywordsToSet(String keywords) {
    if (keywords == null || keywords.isBlank()) {
        return new HashSet<>();
    }
    String[] parts = keywords.split(",");
    Set<String> set = new HashSet<>(parts.length);
    for (String part : parts) {
        String trimmed = part.trim();
        if (!trimmed.isEmpty()) {
            set.add(trimmed);
        }
    }
    return set;
}
```

#### 2.4.2 新增辅助方法：查找重复规则

```java
/**
 * 在指定 templateId 下查找与目标 keywords 集合匹配的已有规则。
 * 如果有多条重复，按优先级返回：isActive=1 且 matchOrder 最小的那条；
 * 如果没有激活的，返回 matchOrder 最小的那条。
 *
 * @return 匹配的已有规则，若无重复返回 null
 */
private SmartMatchRule findDuplicateRule(Long templateId, Set<String> keywordSet,
                                          List<SmartMatchRule> existingRules) {
    SmartMatchRule candidate = null;
    
    for (SmartMatchRule existing : existingRules) {
        Set<String> existingSet = parseKeywordsToSet(existing.getKeywords());
        if (keywordSet.equals(existingSet)) {
            // 集合相等，视为重复
            if (candidate == null) {
                candidate = existing;
            } else {
                // 优先级：isActive=1 优先，其次 matchOrder 小优先
                boolean currentIsActive = Integer.valueOf(1).equals(existing.getIsActive());
                boolean candidateIsActive = Integer.valueOf(1).equals(candidate.getIsActive());
                
                if (currentIsActive && !candidateIsActive) {
                    // 当前规则激活，候选未激活 → 替换
                    candidate = existing;
                } else if (currentIsActive == candidateIsActive) {
                    // 激活状态相同 → 取 matchOrder 较小的
                    int currentOrder = existing.getMatchOrder() != null ? existing.getMatchOrder() : Integer.MAX_VALUE;
                    int candidateOrder = candidate.getMatchOrder() != null ? candidate.getMatchOrder() : Integer.MAX_VALUE;
                    if (currentOrder < candidateOrder) {
                        candidate = existing;
                    }
                }
                // 如果当前未激活而候选已激活，保留候选
            }
        }
    }
    return candidate;
}
```

> **性能说明**：每次训练查询一次该模板的所有已有规则，在内存中循环比较。典型的单个模板规则数通常在几十到几百条，内存比较完全可接受，无需复杂的数据库查询。

#### 2.4.3 改造后的保存逻辑（替换第239-275行）

```java
// ========== 替换以下代码（原第239-275行） ==========

// 7. 查询该模板已有规则（用于后续去重判断）
List<SmartMatchRule> existingRules = smartMatchRuleMapper.selectList(
        new LambdaQueryWrapper<SmartMatchRule>()
                .eq(SmartMatchRule::getTemplateId, templateId));

// 8. 保存规则到数据库（去重更新 or 插入）
int order = 0;
for (Map<String, Object> ruleData : rules) {
    // ----- 构建规则对象（与原逻辑一致） -----
    SmartMatchRule rule = new SmartMatchRule();
    rule.setTemplateId(templateId);
    rule.setTaskId(taskId);
    rule.setRuleName((String) ruleData.getOrDefault("rule_name",
            ruleData.get("match_type") + "_" + order));
    rule.setMatchType((String) ruleData.get("match_type"));
    Object level = ruleData.get("match_level");
    rule.setMatchLevel(level instanceof Integer ? (Integer) level : null);

    // keywords
    Object kw = ruleData.get("keywords");
    if (kw instanceof List) {
        rule.setKeywords(String.join(",", (List<String>) kw));
    } else {
        rule.setKeywords(kw != null ? kw.toString() : "");
    }

    // feature_vector - 转为 JSON 字符串
    Object fv = ruleData.get("feature_vector");
    rule.setFeatureVector(fv != null ? objectMapper.writeValueAsString(fv) : "[]");

    rule.setStyleRuleId(ruleData.get("style_rule_id") != null
            ? ((Number) ruleData.get("style_rule_id")).longValue() : null);

    // threshold
    Object thr = ruleData.get("threshold");
    rule.setThreshold(thr instanceof Number
            ? BigDecimal.valueOf(((Number) thr).doubleValue())
            : BigDecimal.valueOf(0.3));

    rule.setIsActive(1);
    rule.setMatchOrder(order);
    rule.setUpdatedAt(LocalDateTime.now());
    // 注意：createdAt 在 insert 时设置，update 时保留原值

    // ----- 去重判断 -----
    Set<String> keywordSet = parseKeywordsToSet(rule.getKeywords());
    SmartMatchRule duplicate = findDuplicateRule(templateId, keywordSet, existingRules);

    if (duplicate != null) {
        // 重复 → 更新已有规则（仅更新非标识性字段）
        duplicate.setFeatureVector(rule.getFeatureVector());
        duplicate.setThreshold(rule.getThreshold());
        duplicate.setRuleName(rule.getRuleName());
        duplicate.setTaskId(rule.getTaskId());
        duplicate.setMatchOrder(rule.getMatchOrder());
        duplicate.setUpdatedAt(rule.getUpdatedAt());
        smartMatchRuleMapper.updateById(duplicate);
        log.info("规则去重更新: ruleId={}, keywords={}", duplicate.getId(), duplicate.getKeywords());
    } else {
        // 无重复 → 插入新规则
        rule.setCreatedAt(LocalDateTime.now());
        smartMatchRuleMapper.insert(rule);
        log.info("规则新增插入: keywords={}", rule.getKeywords());
    }
    order++;
}

// ========== 替换结束 ==========
```

**特别注意**：
- `existingRules` 需要在循环外部一次性查完，避免在循环内反复查询数据库。
- `findDuplicateRule` 时，新规则自身的 keywords 不应与自身比对——这里查的是数据库中的已有规则，不存在自比对问题。
- `createdAt` 只在 insert 时设置；update 时不修改该字段。
- 更新操作也使用 `updateById`（MyBatis Plus 标准方法），因为 `duplicate` 是从数据库查出的完整实体。

## 三、需求2：服务启动时重置中间状态任务

### 3.1 核心语义

Spring 容器启动完成后，扫描 `smart_match_task` 表中所有状态为 `PENDING` 或 `RUNNING` 的任务，将其统一标记为 `FAILED`，错误信息设为"服务重启，停止训练"。

### 3.2 修改位置：SmartMatchService.java

在 `SmartMatchService` 类中新增一个 `@PostConstruct` 方法。

#### 3.2.1 `@PostConstruct` 方法实现

```java
/**
 * 服务启动时重置中间状态（PENDING/RUNNING）的训练任务为 FAILED。
 * 避免因服务重启导致任务永远卡在中间状态。
 */
@PostConstruct
public void initResetPendingTasks() {
    log.info("服务启动 - 检查并重置中间状态的训练任务");
    
    LambdaQueryWrapper<SmartMatchTask> wrapper = new LambdaQueryWrapper<>();
    wrapper.in(SmartMatchTask::getStatus, "PENDING", "RUNNING");
    
    List<SmartMatchTask> pendingTasks = smartMatchTaskMapper.selectList(wrapper);
    if (pendingTasks.isEmpty()) {
        log.info("无中间状态的训练任务需要重置");
        return;
    }
    
    LocalDateTime now = LocalDateTime.now();
    for (SmartMatchTask task : pendingTasks) {
        task.setStatus("FAILED");
        task.setErrorMessage("服务重启，停止训练");
        task.setCompletedAt(now);
        task.setUpdatedAt(now);
        smartMatchTaskMapper.updateById(task);
        log.info("重置训练任务: taskId={}, oldStatus={}", task.getId(), task.getStatus());
    }
    
    log.info("已重置 {} 个中间状态的训练任务", pendingTasks.size());
}
```

#### 3.2.2 需要新增的 import

在 `SmartMatchService.java` 的 import 块中新增：

```java
import javax.annotation.PostConstruct;
```

> 注意：如果项目使用 JDK 17+ 且 `javax.annotation` 不可用（Spring Boot 3.x），应改为 `jakarta.annotation.PostConstruct`。请根据项目的 Spring Boot 版本选择：
> - Spring Boot 2.x（javax）：`import javax.annotation.PostConstruct;`
> - Spring Boot 3.x（jakarta）：`import jakarta.annotation.PostConstruct;`
>
> 由于 `TemplateApplication.java` 使用 `SpringBootApplication`（无包名前缀特征），请在 pom.xml 或 build.gradle 中确认 Spring Boot 版本。

另外，由于 `selectList` 返回 `List<SmartMatchTask>`，而当前 `SmartMatchService.java` 已导入 `List`，无需再新增该 import。

### 3.3 为什么不放在 SmartMatchTaskService 中？

`SmartMatchService` 已经是训练任务的入口服务（`startTraining` 方法所在类），且已注入了 `SmartMatchTaskMapper`。将启动重置逻辑放在此处最为自然，避免引入额外的循环依赖。

## 四、潜在风险与注意事项

### 4.1 事务问题

- **需求1**的规则保存逻辑已经在 `runTraining()` 内部，该方法**没有** `@Transactional` 注解。每次 `insert`/`updateById` 是独立自动提交的。这是**现有行为**，本次改动不改变事务边界。
- **需求2**的 `@PostConstruct` 在容器初始化阶段执行，各 Mapper 已经可用。每条 `updateById` 独立提交，即使部分失败也不影响其他任务的更新。

### 4.2 并发问题

- **需求1**：`runTraining()` 由 `runTrainingAsync` 异步调用，每次训练有独立的任务 ID。同模板不会同时训练（`startTraining` 方法中有并发检查），因此去重逻辑不会出现并发冲突。
- **需求2**：`@PostConstruct` 在单线程中执行，不存在并发问题。

### 4.3 大集合性能

如果单个模板的规则数量极大（数千条），内存中的集合比较可能成为瓶颈。但根据业务场景，每个模板的规则数通常在数十到数百条，当前方案合适。如未来遇到性能问题，可考虑在数据库层用自定义 SQL 直接比较 keywords（但实现复杂度会显著增加）。

### 4.4 keywords 为 null 或空字符串

- 如果 `keywords` 为 null 或空，`parseKeywordsToSet` 返回空集合。
- 如果已有规则也存在 keywords 为 null 或空的，两者空集合 `equals` 返回 true，会触发去重更新逻辑。这是合理行为——避免产生多条空 keywords 的规则。

### 4.5 matchOrder 语义

训练输出的规则顺序（`order` 变量从 0 递增）即 `matchOrder`。更新已有规则时会覆写其 `matchOrder`，保持与最新训练输出一致。这符合业务直觉：新训练重新定义了规则的匹配优先级。
